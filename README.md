# FindGig

Телеграм-бот — **двусторонняя площадка мелких задач**.

Одни люди публикуют задачи, другие листают их и берутся. Когда заказчик
выбирает исполнителя, бот **сразу меняет их контактами** — дальше они
договариваются сами.

Двуязычный: пользователь выбирает русский или английский при первом запуске.

---

## Как это работает

**Заказчик** 🔎

1. Выбирает тэг (дизайн, код, видео, тексты, звук, другое)
2. Пишет описание задачи
3. Публикует — задача уходит в общую ленту
4. Получает уведомление на каждого откликнувшегося
5. Выбирает одного — и получает его контакт

**Исполнитель** 💼

1. Листает ленту открытых задач, может отфильтровать по тэгу
2. Жмёт «Берусь» или «Дальше»
3. Получает все задачи, на которые откликнулся, в разделе «Мои отклики»
4. Когда его выбирают — получает контакт заказчика

**Мэтчинг.** На одну задачу могут откликнуться сколько угодно человек.
Заказчик выбирает одного. Задача закрывается, контакты выдаются обеим
сторонам одновременно, остальным откликнувшимся приходит уведомление,
что задача закрыта.

---

## Что уже учтено

Такие вещи обычно всплывают уже у клиента, поэтому они сделаны заранее:

- **Свою задачу нельзя взять.** В ленте исполнителя свои задачи не показываются.
- **Пропущенное не возвращается.** Нажал «Дальше» — эта задача больше не всплывёт.
- **Повторный отклик не дублируется.** На уровне базы, а не проверкой в коде.
- **Задачу нельзя закрыть дважды.** Если заказчик успел выбрать раньше — второму
  контакты не выдаются, он получает честное «задача уже закрыта».
- **Без `@username` сделка не состоится.** Бот предупреждает об этом при запуске
  и даёт ссылку на профиль как запасной вариант.
- **Пользовательский текст экранируется.** Имя вида `<b>зло</b>` не сломает
  разметку сообщения ни у заказчика, ни в админке.
- **Админка закрыта фильтром на уровне роутера**, а не проверкой внутри
  каждого обработчика.

## Запуск

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows
# source .venv/bin/activate     # Linux и macOS
pip install -r requirements.txt
```

Скопируйте `.env.example` в `.env` и заполните:

| Переменная | Что это |
| --- | --- |
| `BOT_TOKEN` | токен от [@BotFather](https://t.me/BotFather) |
| `ADMIN_IDS` | ваш ID для `/admin`. Узнать: [@userinfobot](https://t.me/userinfobot) |
| `PROXY_URL` | нужен только если `api.telegram.org` блокируется провайдером |

```bash
python selftest.py          # проверка настроек и переводов, токен не нужен
python tests/test_flow.py   # весь сценарий площадки целиком, токен не нужен
python bot.py               # запуск
```

## Проверка перед сдачей

```bash
python selftest.py
```

54 проверки: тэги, **полнота переводов на обоих языках**, отсутствие пустых
строк, все ключи из кода, логика базы, мэтчинг, права, экранирование.

Отдельно проверяется, что **в русском и английском наборе ключей нет расхождений** —
самая частая ошибка в двуязычном боте это забытый перевод, который всплывает
у пользователя как `status_open` вместо слова.

```bash
python tests/test_flow.py
```

52 проверки: полный сценарий с двумя исполнителями через подменённый сетевой
слой — от выбора языка до обмена контактами и уведомления проигравшему.

## Если Telegram API недоступен

В России `api.telegram.org` блокируется на уровне TCP: **пинг проходит,
а соединение не устанавливается**, поэтому бот запускается без ошибок и молчит.

```bash
curl -s -o NUL -w "%{http_code}" --max-time 15 https://api.telegram.org
```

`000` — соединения нет, впишите `PROXY_URL` в `.env` или включите VPN.
Для постоянной работы лучше сервер за пределами России.

## Настройка под себя

**`config.py`** — единственный файл, который нужно править:

- `BRAND` — название площадки (оно же ставится в имя бота через `setMyName`)
- `TAGS` — список тэгов. `key` латиницей, `ru` и `en` — подписи
- `LANGUAGES`, `DEFAULT_LANG` — языки
- `MIN_DESCRIPTION`, `MAX_DESCRIPTION`, `LIST_LIMIT` — ограничения

**`i18n.py`** — все тексты. Два словаря, `ru` и `en`, с одинаковым набором
ключей. Добавить язык — дописать словарь и добавить код в `config.LANGUAGES`.

## Структура

```
findgig/
├── bot.py                 точка входа, сборка роутеров
├── config.py              настройки: бренд, тэги, лимиты
├── i18n.py                все тексты на двух языках
├── database.py            SQLite: люди, задачи, отклики, пропуски
├── keyboards.py           клавиатуры, собираются по языку
├── utils.py               экранирование, контакты, обрезка текста
├── handlers_common.py     /start, выбор языка, меню, помощь
├── handlers_customer.py   публикация задачи, отклики, мэтчинг
├── handlers_performer.py  лента, отклик, пропуск, фильтр по тэгу
├── handlers_admin.py      /admin: статистика, списки, рассылка
├── selftest.py            54 проверки без токена
└── tests/test_flow.py     52 проверки сценария без токена
```
